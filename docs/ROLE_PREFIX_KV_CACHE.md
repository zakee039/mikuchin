# 角色级 KV 前缀缓存：设计与验证

## 目标与现状

按钮拟放在「角色配置 → 角色卡」操作区，名称「计算 KVcache」。它最终必须完成真实 Prefill、保存 KV、注册到 Mikuchin 基础服务，而不能只存一个角色文字哈希。

目前已把系统提示词调整为：**角色基础信息 → 世界书常驻内容 → 动态世界书/Markdown 检索 → 工作流（最后）→ 会话消息**。角色信息与常驻世界书才是跨对话共享的稳定前缀候选；工作流初始化、检索和动态条目不能提前固化。

## 实测与价值

2026-11-03 用当前 Gemma 分词器检查已有一张角色卡，角色基础信息约 **880 Token**；构造三个不同的动态后缀，最长共同前缀约 **887 Token**。这是 Token 重合检查，不是实际 KV 恢复或速度测试。对低速 Prefill 的本机环境，值得继续做真实缓存实验。

## 必须补齐的机制

当前 PolyStrata 的 SAVE/RESTORE 面向包含会话内容的完整 KV 快照。它无法保证只缓存角色前缀；现有 warm_start 也只保存一个模型级预热前缀，尚无多角色注册表。

1. 引擎增加 **prefill-only 快照**能力：必须保证保存的是完整指定 Token 前缀，不包含任何生成 Token。
2. 注册表按模型权重、分词器、聊天模板、KV 格式、角色卡、身份与常驻世界书建立复合指纹，各模型独立。
3. 点击按钮时先保存角色配置，再进行三组工作流/动态提示词实验，实际计算 Prefill 时间、复用 Token、快照大小、命中率，并注册有效 KV。
4. 新对话优先检查完整会话 KV，未命中时才检查角色级稳定前缀；严格验证 Token ID 前缀完全相同，再恢复 KV 并追加动态内容。
5. 任何指纹变化、模板/模型切换、恢复错误或工作流差异都必须回退完整 Prefill；不能靠近似文本匹配复用 KV。

**目前只完成了提示词重排和前缀长度实验。实际 KV 注册按钮与原生 prefill-only 快照尚未实现；不要将其描述为已完成。**
