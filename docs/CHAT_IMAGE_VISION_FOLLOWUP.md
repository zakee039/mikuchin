# Mikuchin 聊天内生图：视觉回复与图片修改

## 生图后单次视觉回复

聊天中的 `polystrata__generate_image` 成功后，模型不再仅显示固定的「图片已生成」：

1. 生图模型完成、图片存入当前会话图像目录；若有 4× 超分产物，优先把超分前的原图交给视觉编码器，减少无谓的解码开销。
2. 将**刚生成的图片**、本轮用户意图、当前角色上下文作为**临时**输入，再调用当前 LLM 一次。
3. 该次调用固定 **关闭思考、禁用全部工具、正文最多 256 Token**，与该会话通常的采样设置独立。Gemma 的视觉图像编码仍按模型配置（当前 `vision.max_tokens=300`）执行，不把视觉输入计入这 256 个输出 Token。
4. 只将真正生成的陪伴式文字显示、保存为回复；内部视觉提示和图片文件路径**不进入聊天历史**。失败、视觉不可用或输出为空时只回退到「图片已生成。」；取消时不再补发回复。

设计要点：**绝对不能在视觉收尾中再调用生图工具**，也不能用普通带思考、多轮工具的聊天递归继续。

## 后续对话与图片编辑

- 每个会话的最新生图文件由服务端在**生成成功时**注册；另一会话的图片不能通过猜测文件名变成修改来源。删除会话时同步移除该注册。
- 当用户提到「这张图」「眼睛再大一点」「你今天穿的外套好漂亮」等与图片相关的话，模型会在该轮收到最新图片作为视觉上下文；完全无关的普通聊天不重复传图。
- 对较含糊的衣服、眼睛、姿势等词，仅在生图后最近三轮用户消息内触发；明确提及「图片/刚才那张」的消息可以较晚引用。
- 工具增加 `edit_previous`：需要修改图片时，把该会话最近生成的图片传给现有 Qwen Turbo `--ref-image`（或 SDXL `--init-img`）而不是用零参考的文生图。人物身份弱参考与上一张图片的编辑参考不得互相覆盖。
- 更改输入图像并非严格的区域修补：Qwen Turbo 仍可能改动未明确要求的其他细节；如需要像素级保留，之后应评估局部遮罩／inpainting。

以上所有状态归服务端会话管理；不额外设计按浏览器/手机区分的角色视觉记忆。视觉编码器已有按图片内容哈希的缓存，但把图像再次送入 Prompt 仍消耗上下文 Token 和必要的预填充计算。
