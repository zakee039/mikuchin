# 生图任务中心与第三方 API 长耗时排查（2026-11-19，尚未发布）

## 任务中心

- 生图页下方「图像任务」纵向展示最近 40 条生成任务。每次提交先在前端显示占位状态，服务器返回 `img-*` ID 后以数据库记录为准；关闭页面与更换设备均可恢复。
- 1.8 秒轮询一次服务器任务列表，单任务独立显示模型、提示词摘要、尺寸、阶段、步数、用时和错误信息；仅已完成任务在行尾显示缩略图，点击查看原图。NSFW 默认遮罩，单图揭示不改变全局 NSFW 选项。服务器端按 `kind=generate` 返回生图任务，最近 40 条之外的进行中任务也必须保留显示。
- 失败/中断条目提供「修改后重试」（填回最多 180 字提示词摘要，由用户检查模型、参考图、参数后手动提交）和「复制错误」；已结束任务可以只删除记录，也可「清空已结束」。删除不删除画廊中的图片，执行中的任务不能删除。不对付费 API 自动重试。
- 不再把已完成图片拼接到生图表单下面；产图只出现于任务对应行右侧（画廊依然可以查看索引中的图片）。
- `image-jobs.sqlite3` 迁移新增 `profile_id`、`prompt_summary`、`requested_size`，旧任务保留。仅保存最多 180 字的提示词摘要，**不**持久化参考图、完整请求或 API 密钥。
- 本地 GPU/聊天/本地 4x 使用原有单工作线程；第三方 API 使用独立调度队列，按每个服务的 `concurrency` 限制并行任务数（**1～20**），全局待完成任务限制由原有 12 调整为 **80**，保证 20 并发不会先被队列上限阻挡。后台线程不依赖浏览器生命周期。

## 每个 API 独立的超时

- 每个 API 服务独立保存 `concurrency`（**1～20，默认 1**）和 `timeout_seconds`（30～1200，默认 240）；在 API 编辑弹窗配置。实际生成及下载阶段使用该服务的读取超时；连接超时仍为 15 秒。
- 超时并不保证对端停止生成，**不得自动重试**，以免重复扣费。`requests` 的 read timeout 表示连续某次 socket 读取无数据的等待上限，不是严格的任务总墙钟上限。
- 用户「鑫旺Neko」服务保持独立 1200 秒超时。2026-11-19 本轮重启后，服务端实际返回其**现有并发配置为 4**；本轮只放宽允许范围，**没有擅自改动该服务的并发配置和代理开关**。

## 方案核对与已知边界

| 之前定的功能 | 现在的实现 |
| --- | --- |
| 每次提交立即出现任务 | 先显示 `submitting` 占位，服务返回真实任务 ID 后替换 |
| 任务独立实时状态、阶段、用时 | 任务卡片独立显示；服务端 1.8 秒轮询，非服务端主动 SSE 推送 |
| API 按服务独立并发，和本地单任务队列隔离 | 1～20 并发的独立 API 队列；本地/聊天/GPU 单工作线程；全局积压上限 80 |

| 跨页面、跨设备恢复 | SQLite 保存任务元信息；服务进程重启时原运行任务标记为 interrupted，不会恢复正在执行的网络请求 |
| 失败重试、删除、错误信息 | 可复制错误、手动修改后重试、只删除任务记录、清空已结束；**没有自动原样重放 API 请求** |
| 设置任务队列上限 | **目前为服务端固定 80**，尚无用户可调队列上限 UI（之前仅确定独立 API 并发数是优先实施项） |

## 最终任务设计（后续修订，覆盖上文旧的任务中心语义）

**四状态**：`draft` 草稿、`running` 进行中、`success` 成功、`failed` 失败。排队、请求 API、超分是进行中的阶段，不是第五种状态。旧 `generate` 记录首次初始化时转换旧状态；服务中断不能恢复远端工作，标记失败，原有成功图片不变。聊天和图库超分的内部任务状态保持兼容。

- **编辑按钮始终可见**：草稿编辑直接触碰并沿用原任务 ID，更新 `updated` 排序为最新；进行中、成功和失败编辑都会复制出新的草稿 ID，完整加载至当前表单，原任务不变。
- **重试只在成功/失败出现**：直接由服务端复制原保存快照并创建全新的 `running` 任务，立即排队；不影响当前表单、不覆写旧记录，也不会自动重复重试。历史记录没有完整快照时拒绝假重试并明确解释原因。
- **草稿实时保存**：表单编辑立即展示草稿，输入停止约 280 毫秒后写入桌面 SQLite，串行化写操作，防止响应乱序。新的草稿拥有独立 ID，已存在草稿保持 ID 不变；点击「生成」会将该草稿原位转为 `running`，不再额外新建任务。
- **全部图像参数持久化**：`request_json` 保存完整 positive/natural/negative、模型/服务、尺寸、steps、seed、超分、LoRA、参考图模式及参考图有序列表。`prompt` 用于生成的有效提示词，同时保留独立的 `positive_prompt`，避免仅使用自然语言时无法准确恢复表单。API 密钥继续单独保存在服务端配置，不进入任务表。
- **参考图持久化**：PNG/JPEG/WebP 文件在服务端 `chat/image-job-references/` 以 SHA-256 内容哈希去重存储，单张至多 5MB，最多 8 张；数据库仅存 ID 和显示名称，不保存大段 Base64。编辑时通过带 API Key 的私有只读接口恢复文件到表单；生成/重试由后端将已保存资产按原模型参考模式加载。回收未被任何任务引用的资产时，不删除仍被保存任务复用的参考图片，也不删除画廊的正式产图。
- **最多保留 100 条生图任务**：按 `updated` 倒序显示。满额时先删除最旧成功/失败记录，不自动删草稿和进行中任务；从源任务复制或重试时保护源任务不被此次容量清理删除，空间不足则拒绝新任务。只删除任务记录不会删除结果图片。
- UI 预设「草稿/进行中/成功/失败」四状态。任务右侧只显示其成图缩略图；点击展开原图及 NSFW 遮罩规则不变。`清空已结束`只清理成功/失败，保留草稿和进行中。

**注意**：新格式只对修订后创建的任务具备完整恢复能力。v0.2.10 及更早版本只留有摘要的历史任务，无法逆推出已丢失的原始参考图和未记录参数；「编辑」可以新建部分恢复草稿并告知缺失，「重试」会拒绝原样重放，避免生成错误内容或重复收费。

### 任务计时器修正（本轮已部署）

- `created` 仅表示任务创建（包括草稿），`updated` 用于最新活动排序。**二者均不是生成计时依据。**
- SQLite 增加可空 `started_at` / `finished_at`，无损迁移既有任务。草稿无开始时间；点击生成后由浏览器记录当次点击时间并随 `activate` 提交，后台验证时间合理性后写入 `started_at`；直接提交和重试新建任务同理。
- 任务排队、API 请求和超分阶段持续从 `started_at` 计算；首次成功/失败时持久化 `finished_at`，后续元数据变更不重置该时间。前端每秒显示 `已运行 HH:MM:SS`，结束后显示固定的 `耗时 HH:MM:SS`。
- 旧版生图历史原本没有开始时间，**不从 `created` 或 `updated` 伪造精确开始时间**，统一提示「旧记录 · 起点未记录」。任务/图片/参数均保持原样。
- 安全备份 `chat/backups/image-jobs-before-time-fields-20261119.sqlite3`（11 条记录、SQLite `integrity_check=ok`）；无进行中任务且模型未加载时才重启桌面启动器/后端。重启后 `/health=ok`、模型已重新加载、API 返回 `started_at` 和 `finished_at`、11 条历史记录及新字段全部验证，未调用付费生图。

### API 网络阶段诊断及并发隔离审查（最新修订）

- **错误语义修正**：`requests.ReadTimeout` 也可能由 HTTPS TLS 握手等早期网络操作触发，因此报错必须写实际 monotonic 耗时与最后已知阶段，不得把 `(connect=15, read=1200)` 的前 15～20 秒超时宣称为等待了 1200 秒。收到 HTTP 响应头之前，只能可靠归类为 `request_headers` 阶段（可能涉及 DNS/TCP/TLS/上游首字节），不得宣称精确分辨所有底层子阶段。
- **真实响应阶段**：POST 使用 `stream=True`，响应头和响应体分开处理；JSON 响应最多 40 MiB，在接收过程中逐块计数。图片 URL 下载也分别记录下载响应头与响应体字节数，所有 Response 在正常/异常路径均关闭。断流、写超时、连接超时、响应体读取超时区分错误类型与最后阶段；不自动重放付费 POST。
- **隐私保护**：`service.log` 增加 `[mikuchin:image-api]` 日志，含 job ID、直连/代理、阶段、实际耗时、HTTP 状态、接收字节数及异常类别；**不记录提示词、参考图、API Key、带认证的代理 URL 或返回图片内容**。API Job 后端队列同时记录 `[mikuchin:image-pool]` 当前 profile 的活动并发与允许上限，方便对照故障是否与同时执行的任务相关。
- **超时配置**：各 API 独立 `connect_timeout_seconds`（5～60，旧服务默认 15）和 `timeout_seconds`（30～1200，旧服务默认 240）；网页 API 服务编辑对话框分别显示连接/TLS、读取超时。此次添加设置不会改变现有服务的代理、并发、密钥或已有读取超时配置。
- **并发审计结果**：每次生成新建独立 `requests.Session()` 并关闭；任务排队/数据库记录/结果文件名各自隔离，各服务独立并发计数。模拟并发测试验证 4 条真实输出互不混用、两家服务并行不互相堵塞，以及单服务并发上限 20。不同任务仍可能共享本机网卡、Mihomo 出口和中转站额度；无法在客户端消除上游资源竞争，出现频繁短超时时建议先对该 API 降低并发进行对照。
- **无收费调用的验证**：`python -m serve.test_mikuchin_image_api_transport` 6 个模拟故障/成功/并发测试、`python -m serve.test_mikuchin_image_jobs` 18 个任务回归测试、前端 13 个 Node 测试通过；无外部付费生图调用。服务重启是否完成需以运行中的 `/health` 和网页实际版本为准。
